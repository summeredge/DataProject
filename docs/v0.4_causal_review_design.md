# v0.4 因果候选复核设计（第三层）

## 1. 目标边界（Scope）

### 1.1 v0.4 要解决的问题
v0.4 面向 **v0.3 初筛结果之后** 的第三层复核：
- 对 `ranked_features.csv` 与 `causal_review_candidates.csv` 中的候选变量做更严格的“因果候选复核”；
- 输出“复核优先级 + 风险解释 + 证据摘要”；
- 用于指导人工机理核查与后续实验/历史工况回放。

### 1.2 明确不做（Out of Scope）
- 不改动 v0.3 主流程（初筛、打分、Web 主交互保持不变）；
- 不重构 Web；
- 不引入 PCMCI+、Transfer Entropy、APC 建模；
- 不直接输出“最终因果结论”或“因果确定性标签”。

## 2. 输入与输出文件设计

### 2.1 输入文件（最小依赖）
1. `ranked_features.csv`（v0.3 主候选）

## 3. Conditional Granger 的最低实现方案（MVP）

> 目标：在不引入复杂新算法前提下，补一层“受控预测增益”证据。

### 3.1 变量集定义
对单个候选变量 `x` 与目标 `y`：
- 基线模型：`y_t ~ y_{t-1..p}`
- 扩展模型：`y_t ~ y_{t-1..p} + x_{t-l..t-l-k}`
- 条件控制：`+ c_{t-1..p}`（`c` 来自 residual/capacity 控制列）

即比较：
- `AR + Controls`
- `AR + Controls + CandidateLags`

### 3.2 最低统计输出
每个候选输出：
- `variable`
- `best_lag_used`
- `base_rmse`
- `full_rmse`
- `lift_ratio`
- `f_stat`（可选）
- `p_value`
- `passes_min_effect`（如 lift_ratio >= 阈值）
- `passes_significance`（如 p_value <= 阈值）
- `review_note`

### 3.3 最低判定建议
仅用于“复核优先级”加权，不做因果判定：
- `strong_support`: 显著且效果量达标
- `weak_support`: 显著性或效果量仅满足其一
- `no_support`: 两者均不满足

## 4. Direction Consistency（方向一致性）约束方案

### 4.1 设计目的
避免“统计相关有信号，但方向不稳定/逻辑冲突”的候选进入高优先级复核。

### 4.2 一致性维度
1. **滞后方向一致性**：
   - 候选在不同窗口/工况下，领先/滞后方向是否稳定；
2. **符号一致性**：
   - 相关方向（正/负）是否频繁翻转；
3. **控制后方向一致性**：
   - 残差化后方向是否保留。

### 4.3 最低输出字段
`direction_consistency_review.csv`：
- `variable`
- `window_count`
- `lead_lag_consistency`
- `sign_consistency`
- `residual_direction_consistency`
- `direction_consistency_score`（0~1）
- `direction_consistency_level`（high/medium/low）
- `direction_note`

### 4.4 约束规则（用于优先级，不用于结论）
- 一致性低：降级复核优先级；
- 一致性中：保持；
- 一致性高：可升档（需结合风险项）。

## 5. Force Include 的人工复核逻辑

### 5.1 原则
`force_include_variables` 代表业务强关注位号：
- 必须进入三层复核队列；
- 即使统计证据较弱，也不直接剔除；
- 但需明确标记“人工指定”来源，避免被误读为算法强支持。

### 5.2 建议字段
在 `causal_review_priority.csv` 增加：
- `force_included`（bool）
- `force_include_reason`（manual/business/historical_incident 等）
- `auto_evidence_level`（strong/weak/none）
- `manual_review_required`（bool）

### 5.3 输出行为
- force include 且证据弱：保留在队列中，但标注“优先人工机理复核”；
- force include 且证据强：可进入最高优先级组。

## 6. risk_flags 与 causal review 的衔接规则

### 6.1 风险分层使用
沿用 v0.3 风险标志，不改主算法；在 v0.4 仅做复核衔接：
- 强风险（如闭环、强公式泄漏、明显共同负荷）优先降档；
- 弱风险（如 formula_like、lag_boundary、低模型提升）用于提醒解释。

### 6.2 建议衔接映射
- `common_capacity_driver`：要求检查控制列充分性，默认降一级；
- `closed_loop_suspect`：标记“反馈风险”，需要额外时序切片复核；
- `strong_formula_leakage`：默认不进入高优先级；
- `unstable_over_time/unstable_across_regimes`：要求窗口化复核后再定档；
- `control_variable_reference`：保留为“控制基准参考”，不作因果候选主证据。

### 6.3 解释输出
在 `causal_review_priority.csv` 增加：
- `risk_penalty_applied`
- `risk_explain`
- `final_review_priority`

---

## 7. 最终输出口径（关键约束）

v0.4 只输出：
1. 复核优先级（谁先看）
2. 风险解释（为什么升/降档）
3. 证据摘要（conditional Granger + direction consistency + 既有风险）

**不输出最终因果结论**，不使用“已证实因果/非因果”措辞。
